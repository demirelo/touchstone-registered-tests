**Goal:** Implement and run the six exploratory stress tests pre-stated on 2026-10-18 in `docs/research/2026-10-18-positioning-and-post-evaluation-plan.md` section 4, against the frozen R3 and the three baselines, and report every result.

**Architecture (v3, after the round-1 and round-2 reviews of Sol high and Astra high, `docs/exploratory/roster/`):** Six new searchable policy families in one new module `sim/policies/exploratory.py`, each a `Family` (bounded knobs, binary knobs, `clip` last, honest point equal to honest-max), built from one shared two-mode action (honest round or cheat round, D1's action shape) plus a per-family gate that decides when to cheat and when to replace the identity. One new script `scripts/explore_attackers.py` runs the registered pipeline per cell (twin search, attack search with registered incumbents, exact corners, a cross-rule bank pass, reference selection in registered order, dev-val evaluation) by calling the frozen functions of `sim/search.py`, `sim/reference.py`, and `sim/cell.py`. No frozen file changes.

**Tech Stack:** Python 3.12, numpy, cma (already used), pytest, uv; Runpod CPU pods for the runs.

**Spec:** `docs/research/2026-10-18-positioning-and-post-evaluation-plan.md` section 4 (binding: the six tests, the rules for running them) and `docs/superpowers/specs/2026-10-14-touchstone-simulator-design.md` (sections 4 to 8) and `experiments/locked.yaml` for the registered pipeline the tests must mirror.

## Review Focus

1. Honest points through noise: every family's honest point must reproduce `HonestMax` over whole episodes, including Gaussian false failures, the bans they cause, and scheduled-reset rounds (reset switches are binary and zero at the honest point).
2. Identity timing: the harness asks for actions before it creates a replacement, so the exit round is the new identity's first round (age 0) and the next round is age 1; ban returns never reset age; history entries belong to the identity that served.
3. Gross funding is not profit: `history.payment` is gross funding; a profit proxy is `payment - refunded - served * (a + b * effort_of_that_round)`, with the effort remembered by the policy.
4. X6 is a coalition: its reference and twin semantics differ from the unilateral benchmark; cached coalition scores must never rank unilateral references; coalition partners are not outsiders in harm or false-ban diagnostics.
5. Provenance and resume: every record binds its inputs by hash (runner and policy code, config, seeds, calibration, salt fingerprint, bank members, source records, coalition membership, smoke flag); writes are atomic; a stale, smoke, or partial record is refused.

## Task 2: The six families

Knob order: bounded knobs, then binary knobs, `clip` last. Shared cheat knobs `u` [0, 1], `m` [0, 1], `s` [0, 0.3], `w` [0, 2] (D1 domains). Fixed public window W = 10 (the common ban length). Phases: fresh (identity age < W), terminal (T - t <= W, precedence over fresh), established (otherwise). Each history observation is assigned to the phase of the round in which it occurred. Every gate chooses per round between `cheat_action` and `honest_action` and an exit flag; reset switches are binary and zero at the honest point; `x = 1` means exit in the round after one of the identity's audited jobs failed (as `IdentityReplacement`).

1. **X1 audit-hazard (`AH`)**: `u, m, s, w, theta [0, 1], kappa [0, 50], x, clip` (8). Per-phase served and audited counts. Estimate for the current phase b: if `served_b + kappa == 0` use the pooled rate; else `p_b = (audited_b + kappa * p_pool) / (served_b + kappa)`, `p_pool = (audited_all + 1) / (served_all + 1)` (one pseudo-observation at probability 1). Cheat iff `p_b < theta`. Label: a learned audit-frequency threshold by phase; it does not compute the expected-sanction-versus-saving condition, and it cannot see the rule's pacing beyond its own experience.
2. **X2 tranche signal (`TD`)**: `u, m, s, w, theta [0, 0.6], h [1, 30], x, clip` (8). One EWMA per phase of the per-round audited fraction of served jobs (half-life h; rounds without service skipped; each initialised at 1; the fresh EWMA resets to 1 at each exit). Cheat iff the current phase's EWMA < theta. Label: round-level only; neither job-specific effort (one effort per entity per round, `Action.effort`) nor actual tranche membership is observable.
3. **X3 horizon timing (`HS`)**: `u, m, s, w, t0 [0, 1], span [0, 1], z, clip` (8). Cheat iff `t0 * T <= t < min(T, (t0 + span) * T)`, or z = 1 and t >= T - W. Never exits. Two exact diagnostic incumbents per cell, outside the budget and counted: the window [10, 190) with z = 0, and [190, 200) with z = 0 (cheat knobs from the cell's best point). Label: the audit stock is not observable; the window is a time proxy against each rule's public pacing.
4. **X4 reset option (`RO`)**: `u, m, s, w, lambda [0, 3], n_age [0, 40], x, clip` (8). Honest while identity age < round(n_age), cheat afterwards. Value proxies: EWMA (half-life 10, fixed; initialised at the first observed value) of the profit proxy, `V_e` for established rounds and `V_f` for fresh rounds. The policy records each action round's phase, effort, and whether it was eligible to serve (not banned at the time of acting) before enforcement; every served round updates the estimate of its recorded phase exactly once, including a round whose failed audit then causes a ban, with that round's refund and cost applied before the update; rounds without service are skipped. In the round after a failed audit that bans the identity until round B, if x = 1: with lambda = 0 always exit; with lambda > 0 exit iff `max(0, min(B, T) - t) * max(V_e, 0) > lambda * W * max(V_e - V_f, 0)` and `V_e - V_f` is defined (else exit). Label: learned value proxies, not identified continuation values.
5. **X5 aging (`AG`)**: `u, m, s, w, n_age [0, 40], x, clip` (7). Honest while age < round(n_age), cheat afterwards; x = 1 exits after a failed audit. The simple control for X4.
6. **X6 simultaneous entrants (`SE`)**: `u, m, s, w, P [1, 50], x, y, clip` (8), cell parameter `c` in {1, 2, 5} (coalition size including the focal; c = 1 is the matched single-member control). Members: the focal (median position) and the c - 1 entities nearest to it in the `positions` score order, ties to the lower index; each member has its own policy instance. Every member cheats when not banned; if y = 1 every member exits at each t >= 1 with `t mod round(P) == 0` (synchronised, no communication); if x = 1 also after its own failed audit. Controls at the selected attack point, for c > 1: (i) staggered scheduled resets: with P' = round(P) and K = floor((T - 1) / P') synchronised resets per member (rounds kP', k = 1..K), member j (j = 0..c - 1) resets at rounds kP' - o_j, k = 1..K, with o_j = floor(j P' / c); every member keeps exactly K scheduled resets inside rounds 1..T - 1, and the reset rounds are distinct across members exactly when P' >= c; when P' < c the control is labelled partially staggered and its overlap (number of rounds with two or more scheduled resets) is reported; (ii) a synchronised and staggered pair with x = 0, which isolates scheduled timing; failure-triggered resets (x = 1) are counted separately, since they can differ in number and can coincide; y = 0 has no scheduled-timing intervention and gets no staggered control. Label: a joint deviation; the objective is focal profit under a coordinated profile, not coalition profit.

**Interfaces — Produces:** `EXPLORATORY_FAMILIES: dict[str, Family]` (`X1-AH`, `X2-TD`, `X3-HS`, `X4-RO`, `X5-AG`, `X6-SE`); `coalition_members(cfg, focal, c) -> tuple[int, ...]`; `scheduled_resets(P, c, T, staggered: bool) -> list[list[int]]` (per member, the scheduled reset rounds).

## Task 3: Cell runner (`scripts/explore_attackers.py`)

**Interfaces — Consumes:** `cma_search`, `Objective`, `corner_controls`, `best_archived` (`sim/search.py`); `reference_candidates`, `select_reference`, `evaluate_gain`, `seed_rows`, `ROW_FIELDS` (`sim/reference.py`); `Cell`, `SeedCache`, `run_focal` (`sim/cell.py`); `cell_config`, `load_calibration`; `make_rule`, `proposed_params`; `positions`; `bound`; `restart_spread`, `twin_vs_honest`, `doubling_check` (`sim/search_checks.py`).
**Produces:** `job_for_x(rule, family, c=None, smoke=False) -> dict`; stages `x_search`, `x_bank`, `x_reference`, `x_evaluate`, `x_report`; CLI `--stage {search,bank,reference,evaluate,doubling,report,all} --rules --families --workers --out results/exploratory --smoke --pilot`.

Unilateral families: the twin and attack searches are the frozen `twin_search` and `attack_search`. X6: local wrappers call `cma_search` with the registered settings, starts, and incumbents and a local `CoalitionObjective` whose `eval_knobs` builds the cell with the c - 1 members playing the same knobs (the twin projects every member, so all are clipped). Reference for X6: every candidate is re-scored with honest opponents before ranking; coalition-derived `known_profit` and `known_normalized` are cleared; archive groups are ranked by these new scores; registered group order and exact de-duplication are kept. Evaluate for X6: attack and clipped runs with the coalition, reference and honest-max runs with honest opponents; the X6 gain is a coalition-versus-unilateral comparison. Local corrected diagnostics: focal identities (not market identities), member versus outsider bans, false bans, and lost capacity (excluding retired identities), fresh served jobs and their audit coverage per round (quota saturation).

Bank: built only from a complete, immutable source manifest (all four rules' search records for the family present and hash-verified); members in canonical order (rule order B1, B2, B3, proposed; attack best, then twin best; then the family's exact corners), exact-key de-duplication, ties to the earlier member; X6 members transfer across sizes and are re-scored at the target size. Each cell evaluates members without a known value, replaces its incumbent only if a member scores strictly higher on dev-train, then evaluates the projection (the frozen `stage_bank` logic, reimplemented because `sim/bank.py` admits only registered families); projected members enter the reference candidates. A parity test runs the local bank and the frozen `Bank` on the same registered D2 fixture and requires identical rankings, replacements, and projections, ties included.

Provenance: every record carries `git_commit`, SHA-256 of `scripts/explore_attackers.py` and `sim/policies/exploratory.py`, the rule's parameter hash, config, seeds, calibration hash, salt fingerprint, coalition membership, smoke flag, bank hash, and its source records' hashes; records are written atomically (temporary file, then rename); a later stage refuses stale, smoke (in a real run), or missing inputs; a completed stage is skipped on resume.
