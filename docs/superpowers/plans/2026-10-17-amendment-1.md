# Amendment 1 Implementation Plan (v4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Register a disclosed amendment to the lock of 2026-10-17 that adds an H3 comparative clause with its own admitted bound and a binding design-and-tuning registration for the proposed rule, without touching `experiments/locked.yaml` or any registered artifact.

**Architecture:** The amendment is a YAML file outside the settings hash plus a second predicate beside the first. A new module `sim/amendment.py` holds the paired statistic `gain_diff`, its reserved seed layout with remedy factors, its 12-endpoint gate at n = 40, its strict admission, and the canonical amendment hash; a new script `scripts/coverage_ext.py` runs that extension on the six registered cells with B3 as the stand-in for R* against B2 (one cell per pod, then merge); `scripts/amend.py` validates the extension report against the lock, the base report, and the amendment, then records its hash and consequences in the amendment file; `sim/claimcheck.py` and `scripts/check_claim.py` evaluate and print both verdicts with the original H2 clause inside the amended conjunction; `sim/manifest.py` adds the final H3 stress-test cells (beta 0.05, median, n = 40) so the final evaluation produces the rows the clause needs.

**Tech Stack:** Python 3.12, numpy, scipy, pandas, pyyaml, pytest, uv; Runpod CPU pods for the extension study.

**Spec:** `results/roster/consensus-final.md` (sections 2 to 5) and the two plan reviews `results/roster/sol-plan-r1.md`, `results/roster/astra-plan-r1.md` (every MATERIAL objection there is a requirement here), with `docs/superpowers/specs/2026-10-14-touchstone-simulator-design.md` sections 4.0, 4.2, 6.2, and 8 as the authority on the admissible class, tuning, H3, intervals, coverage scoring, and the decision rule.

## Global Constraints

- `experiments/locked.yaml` is never edited; the `claim` block is inside `settings_hash` (sim/locked.py:40) and every registered artifact carries that hash. Registered artifacts (tuned files, calibrations, coverage report and cells, pilots) are never rewritten; `scripts/amend.py` verifies their hashes against the lock.
- The original predicate (`evaluate_claim`) and its output are unchanged; the amended verdict is reported beside it, never instead of it.
- Amended clause: family `D2+H3`, position `median`, beta 0.05, final-eval seeds, n = 40. Absolute part on H3 for R*: eff lower 95% >= 0.90, gain upper 95% <= 0.30, audit cost <= B in every seed. Comparative part per baseline B in {B2, B3}: paired per-seed `gain(B) - gain(R*)`; PASS requires both lower 98.75% bounds >= 0.10; FAIL if either upper 98.75% bound < 0.10; otherwise INCONCLUSIVE. Amended PASS = original H2 rule clause PASS and H3 absolute PASS and comparative PASS and the `gain_diff` sides admitted; FAIL if any of these is FAIL; otherwise INCONCLUSIVE.
- H3 is "the public identity-replacement stress test on fresh final-evaluation seeds", never "held out", in every document and console line; the internal manifest section name `heldout` is explained in the note.
- Extension study: the six registered cells of `experiments/coverage_cells.json` (verified against `select_cells` recomputed on the universe); statistic `X_s = [(pi_B2,attack - pi_B2,ref) - (pi_B3,attack - pi_B3,ref)] / (S*_s / N)` with each rule's own frozen attack knobs and its own selected reference candidate at the cell's family and position (abstain reference = profit 0); studentized bootstrap only; n = 40 only; base M = 35,000, base R = 4,000; both 98.75% sides; conservative scoring, thresholds, threshold check, joint fixture (6 cells x 2 endpoints), power, and the remedy order (1,1), (2,1), (2,2) as in sim/coverage.py.
- Seeds: `seeds_ext` start 6,600,000, block 400,000 per cell: positions 0 to 69,999 reserved for the pool (base 35,000, doubled 70,000), positions 70,000 to 389,999 reserved for the n = 40 replications (base 4,000 x 40 = 160,000, doubled 320,000); six blocks end at 9,000,000; disjoint from dev-train, dev-val, calibration, the base coverage range [3,000,000, 6,600,000), and the final-eval range [10,000,000, 20,000,000); `load_amendment` refuses any overlap.
- Every report, console line, and document that states the amended verdict carries the sentence: "Proxy admission on development distributions with B3 standing in for R*; this is not nominal coverage for comparisons involving the selected R*."
- Compute allowance before launch: 4 trajectories per seed, 6 x (35,000 + 160,000) x 4 = 4,680,000 episodes at base sizes, up to 9,360,000 with both remedies; measured throughput from a local `--smoke` run and the first pod hour decides the calendar; the amendment is not tagged before `amend.py --check` passes on the copied report.
- Module rules of docs/lock-runbook.md "Freeze day" are untouched; no paid API calls in tests; commits unsigned (`git -c commit.gpgsign=false`) with the Co-Authored-By trailer; the user signs. Every new CLI resolves default paths under `--repo`, never the caller's cwd.

## Review Focus

- A cell whose selected reference for B2 or B3 is `abstain`: `gain_diff` uses reference profit 0 for that rule and never raises (Task 1).
- H3 rows from the final-eval sweep with a duplicate seed, a wrong namespace, stale parameters, or no row for one rule: the amended verdict is INCONCLUSIVE with the reason, or the records are refused before evaluation, never an exception or a silent partial merge (Tasks 3 and 4).
- `scripts/check_claim.py` without an amendment file: original behaviour and output unchanged (Task 4).
- A doubled pool or doubled R: the seed layout keeps the base pool and base replications as prefixes and never overlaps (Task 1).
- An extension report that is self-consistent but was produced from a changed tuned file or a changed reference record: `scripts/amend.py` refuses because its provenance differs from the base report's and the lock's (Task 6).
