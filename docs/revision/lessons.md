## 2026-11-11: watchdog stopped on one empty listing after DONE (harness3, scenario 5)
Mistake: before the hard deadline, the watchdog exited on DONE plus one empty listing; a delayed creation behind an ambiguous answer appeared later with no supervision. My first regression test also passed before the fix, because its assertion held when the watchdog quit early.
Guard: `test_r11_watchdog_before_the_deadline_settles_so_a_delayed_creation_is_deleted` (seen RED, then GREEN) and the harness scenario "delayed creation behind an ambiguous answer". Rule: a regression test must assert that the triggering event happened, not only that the bad state is absent.

## 2026-11-11: churn memory preflight measured reused records; worker limit reset per command (churn review r4)
Mistake: the pod-side preflight took peak memory from a child whose task was "skipped" (a valid record existed), so it could admit too many workers; the reduced worker limit lived only inside one `_run_rate` call, so a separate diagnostics command ran at nine workers. The smoke test itself asserted on a skipped measurement and passed.
Guard: the child reports the task status and `memory_preflight` refuses skipped measurements; `memory_workers.json` keeps the lowest limit per memory limit; tests `test_r4_*` (5, seen RED) and the smoke test now assert the refusal on an existing record and a real child run. Rule: a resource measurement must prove the measured work ran (status, record written), not only that a number came back.

## 2026-11-11: churn r5, a reuse path trusted records it could not verify
Mistake: the r4 fix reused a saved memory measurement without checking rule coverage or that draft-4 records carried real-run evidence, and it removed measured jobs from dispatch, so a missing record would stay missing.
Guard: versioned preflight record with per-task "done" statuses and rule coverage; every job goes through `_run_one`; tests `test_r5_*` (4, seen RED). Rule: a cache or reuse path must validate the same things the fresh path proves, and must never stand in for the production record check.

## 2026-11-11: launcher review r11 (reset pod)
Mistake: (a) the watchdog counted empty time before DONE existed, so it could exit with zero settle after DONE; (b) every HTTP error counted as a definite refusal, but a 5xx or gateway error can follow a real creation; (c) `podctl.py reconcile NAME 600` passed 600 as KEEP_ID, not as a timeout; (d) retrying after an ambiguous answer could overlap two pods, which no listing can rule out.
Guard: tests `test_r12_settle_counts_only_after_done`, `test_r12_creation_answers_are_ambiguous_unless_clearly_refused` (10 cases), `test_r12_after_an_ambiguous_answer_the_settle_is_long_enough_for_a_late_pod`, `test_r12_fractional_budget_is_passed_as_a_fractional_timeout` (all seen RED). Design guard for (d): an ambiguous answer ends creation for the launch. Rule: prefer a design that removes an unprovable case over code that tries to prove it.
